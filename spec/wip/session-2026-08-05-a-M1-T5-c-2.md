# WIP — M1-T5-c-2 (gpu backend for the nukebench gate runner)

**Session:** session-2026-08-05-a · **Claimed:** 2026-08-05 · **Branch:** `task/M1-T5-c-2-gpu-gate-backend`
**Depends on:** M1-T5-c-1 (done — the ref runner + committed C-900 evidence).

## Goal (tight scope)

Add a **gpu** backend to `run_gate` so a C-900 gate runs in ~seconds/seed on the RTX 4070 (vs
~5 min/seed on ref). Prerequisite for G0c (c-3, the ref-vs-gpu differential). GPU-vs-CPU parity is
already validated (ADR-021, the fast4 Godiva `gpu.` test) — this exposes it through the gate runner.

## Plan

1. **`run_gate`** (`src/app/nukebench/gate_report.cpp`): dispatch `ref|gpu`. The assembly (scenario →
   material + radius → `MaterialLib` + `LayerStack`) is identical for both. Per seed:
   - `ref`: `RefTransport(stack,lib,xs,seed)` → `run_eigen(spec)` → `res.k`, `res.sigma_pcm` (existing).
   - `gpu`: `ns::gpu::gpu_eigen(stack, lib, seed, batch, inactive, active, 256, 128, out)` →
     `out.k`, `sigma_pcm = out.k_sigma * 1e5` (SE of k → pcm). Result is launch-invariant (256/128 is a
     proven config; mirrors the ADR-021 parity test `test_gpu.cpp:650`).
   - **CUDA guard:** the gpu path is `#ifdef NUKESIM_WITH_CUDA` (calls `gpu/eigen.h`'s host-callable
     `gpu_eigen`); `#else` throw `GatesError("gpu backend not built (NUKESIM_WITH_CUDA off)")`.
   - Reject any backend ∉ {ref, gpu}.
2. **CMake:** inside `if(NUKESIM_WITH_CUDA)` (after `nukesim_gpu` is defined, ~L495):
   `target_link_libraries(nukesim_nukebench PRIVATE nukesim_gpu)` +
   `target_compile_definitions(nukesim_nukebench PRIVATE NUKESIM_WITH_CUDA=1)`. And add
   `nukesim_nukebench` to `test_gpu`'s link libs so the gpu-backend test can call `run_gate`.
3. **Test** (`tests/unit/test_gpu.cpp`, the CUDA-only `gpu.` suite so CI stays 168): `run_gate` with
   `backend="gpu"` on G0a (reduced batch) → sane measurements, and the gpu k agrees with the ref
   oracle to within parity (< 600 pcm). Registers as a `gpu.` test → 14→15.
4. **`main.cpp`:** `--backend` help text `ref (default)` → `ref|gpu`.
5. VERIFY: **183 dev** (168 CPU + 15 gpu) / **168 CI** (the gpu path is CUDA-guarded out on CI). Docs.

## Discipline

- The gpu backend is DEV-only (CUDA); CI (CPU-only) compiles the gpu path out → `backend="gpu"` throws
  a clear error there. Anchored counts stay clean: `nukebench.` = 9 (CI), `gpu.` 14→15 (dev-only).
- No change to the committed **ref** C-900 evidence (the ref oracle stays the authority for G0a/G0b).
- `EigenResultGpu.k_sigma` is the SE of k (k-space) — ×1e5 for pcm (mirrors `(res.k-1)*1e5` scaling).

## Findings (append before acting)

- (init) `gpu_eigen(stack, materials, seed, batch, inactive, active, blocks, threads, out)` →
  `EigenResultGpu{k, k_sigma, ...}` (`src/gpu/eigen.h`). The ADR-021 parity test builds the fast4
  Godiva assembly exactly as `run_gate` does and asserts `|gpu.k − cpu.k| < 0.006` — so the gpu path
  in `run_gate` is a proven mirror. The CLI already plumbs `--backend` (main.cpp → cli_gate → run_gate).
