## 2. Origin, intent, product (why the discipline matters)

- **Origin.** Inspired (negatively) by a naive 2D JS criticality "atom" viz that capped at
  ~2000 atoms because it modelled atoms as particles testing every other atom each step —
  **O(N²)/step, single-thread CPU JS.** The owner's thesis: do it **100× better, in 3D, for
  the whole device, with real physics.**
- **The scaling principle (do NOT regress).** Scale is achieved by the *correct* physics,
  which is also the scalable algorithm: **GPU Monte-Carlo neutron TRANSPORT** — track neutrons
  (O(N), independent, ≥1e6/generation on GPU), not atoms; the "atoms splitting" the viz shows
  are **fission EVENTS** = `ref::FissionSource::sites`. Never architect the chain-reaction viz
  as O(N²) all-pairs; the 10–50k rendered "atoms" are a representative SAMPLE of fission sites
  from an engine simulating millions.
- **The product.** Eventual **Steam release** — a visual, interactive 3D sandbox (spirit of
  the owner's *DF-41 Simulator*). **Public MIT GitHub = the ENGINE/spec**; Steam = the polished
  visual `nukestudio` layer (M7). Headless frontends (nukebench, MCTS sweeps) are engine +
  validation, **not the shelf product**. The differentiator vs a novelty sim: **every visual
  is driven by real, benchmark-provable physics** — which is why the gates (and `fast4`) matter
  for the *product*, not just academic rigor.
- **Scope guardrails (hard, `00 §2–§3`).** Public/declassified only; every constant carries a
  citation + status. Classified gaps (exact peak k, Bethe–Feynman coefficients, lens contours)
  are NOT filled — published *bands* only, never invented point values. Interactive single-point
  exploration is in scope (`non_canonical`, never gate evidence); automated search over
  *physical* axes toward an objective is out (enforced by `axis_class` + `ScoreKind`).

## 7. WHAT TO WATCH OUT FOR (traps + hard-won insights — read every one)

### 7.1 The density-coupling insight (the single most important)
`Σ ∝ ρ`. A *bigger* sphere at *fixed* density reads as MORE reactive (less leakage) —
**backwards** for disassembly. For ANY moving geometry use **`ref_eigen_fn_masscons`** (scales
ρ mass-conservingly, `ρ/ρ₀ = (r₀/r)³`), never `ref_eigen_fn` (fixed density, static assemblies
only). It's uniform (bare core exact); the full multi-layer device needs per-layer scaling
(+ `fast4`).

### 7.2 The fusion-architecture boundary (C++ = data; JS = presentation)
`viz/js/main.js` calls `run.compression(t)` / `run.flux(t)` as per-frame JS **closures** —
C++ can't return closures. So the real fusion is: the C++ `generate_run` returns **DATA ONLY**
(tally/run/samples + the emergent detonate/reasons/yield), and the JS binding that *replaces*
`simstub.js` reconstructs the presentation closures from that data. `main.js` is unchanged;
**`simstub.js` is the thing replaced.** The C++ surface is deliberately closure-free. (In the
`viz-seam-coordination` memory.)

### 7.3 The shared working tree with the -e (visualizer) session
The parallel viz session develops in the SAME tree (`C:\NUCLEAR`), so its uncommitted `viz/`
edits + `.zcode/` appear in your `git status`. **Rules:** stage EXPLICIT paths
(`git add <path> …`), NEVER `git add -A` from the root; verify `git diff --cached --name-only`
has no `viz/`/`zcode` before EVERY commit (this session did, every time). `git checkout -b` at
HEAD is safe; branch switches change the branch under -e too. A worktree `C:/nuclear-viz`
(branch `viz/gadgetlab`) exists for -e; migration is the owner's to run.

### 7.4 The `fast4` discipline (never cross this line)
`fast4` = the cited 4-group cross-section dataset (~450 physical values, M1-T4a-2). It is
**owner-provided** and **MUST NOT be invented** — fabricated cross sections are the single
failure the whole provenance discipline exists to prevent. BLK-14 forbids an autonomous session
seeking ICSBEP access. If you need cited Pu xs and it isn't there, use synthetic-but-loadable xs
(tagged SIM, like `RealSphere`/`DemonCoreAssembly`) and say so. Surface the ask; don't stall the
whole session on it (the demon-core work is fast4-independent).

### 7.5 CI / git cadence (this session got bitten)
Space out pushes to `main` — **rapid pushes trigger a GitHub Actions concurrency cancel-cascade**
(benign but confusing). This session pushed a docs commit ~5 min after a merge and CANCELLED the
merge's CI (the code was fine; a later run re-validated). Even a docs push counts. Watch a push's
CI to green (`gh run watch <id> --exit-status`) before layering the next task. **gcc (Linux CI)
finds what MSVC does not** — expect it on new modules; MSVC-clean is not CI-clean. Use
`git commit -F -` with a heredoc (backticks in `-m` execute). Merge only green (`--no-ff`,
message via a temp file: `git merge -F <file>`; stdin/`-F -` does NOT work for `git merge`).

### 7.6 ASCII-only Catch2 test names (this session got bitten TWICE)
A `—` (em-dash) and later a `,` (comma) in a `TEST_CASE` name each broke ctest↔Catch2 name
matching ("No test cases matched") — the filter parser treats them specially. **Keep Catch2 test
titles ASCII with no commas** (the codebase writes "section 5", not "§5").

### 7.7 The bit-identity resume design (M5-T1-c — reuse for the GPU T-resume / M3-T4 hydro)
Checkpoint at a **REFRESH boundary** so the cached eigen (k_p/ν/Λ/shares) is RE-DERIVED by
re-running the deterministic eigen on resume — no `EigenResult` serialized. Geometry is
RECONSTRUCTED from `geom0` + shell.R (disassembly) or t (tier-1), not serialized. Capture
`eigen_calls` BEFORE the refresh so the resumed refresh re-increments it. The sink resumes via
`on_begin(ctx)` [keeps ctx_] then `load_state`. Each state struct owns its own physics-side
serializer (`serialize_accumulator_state`, `serialize_burst_state`); the checkpoint container
(core) stays a generic opaque-section holder (core must not depend on physics).

### 7.8 Protocol traps (from `ONBOARDING §4` — the recurring ones)
Read the module spec (`04`/`05`), not just the data contract (`03`). "Within 1σ" acceptance is a
coin flip (use 3σ + a mean-pull bias check). Never tune a test to pass. A vacuous check proves
nothing. Measure, don't estimate. Probe names must be anchored (`^<module>\.`). Constants from
`ns::consts`, never magic numbers; gate thresholds from `gates.toml`.

### 7.9 The anchored-probe invariant (keep it true)

loaders, geometry, ref, eigen, benchmarks, gpu, kinetics, tier1, tier2, tally, couple, api,
