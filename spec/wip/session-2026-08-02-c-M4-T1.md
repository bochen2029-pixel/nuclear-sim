## Design decisions / findings (append as they happen)
- Device Philox: **reuse** `core/rng/{philox,rng}.h`, do NOT copy. Add `NUKESIM_HD` macro
  (`__host__ __device__` under `__CUDACC__`, empty on host) via new `src/core/hd.h`. Reason:
  the DoD is "device KATs MATCH CPU" — the only way to guarantee that is one source of truth.
  A second device implementation could drift. philox.h's own comment anticipates this.
- Rely on explicit `NUKESIM_HD`, not nvcc's implicit constexpr-is-host-device, so device
  readiness is self-documenting and does not depend on `--expt-relaxed-constexpr`.
- Reuse the portable `uint64` `mulhilo32` on device (NOT `__umulhi`) for M4-T1: it is
  bit-identical to the CPU path by construction. `__umulhi` is a perf substitution → defer to
  M4-T4 with a KAT re-check obligation.
- Reductions: fixed-point **int64** is exactly associative+commutative, so any block/thread
  layout yields the identical int64 total → bit-identity across thread counts is by
  construction. Per-block reduce (shared-mem tree) → int64 partials → deterministic host
  combine. FP atomicAdd forbidden (05 §6); integer atomicAdd would also be exact but the
  block-tree matches the spec's stated design.
- Documented fixed-point SCALE: 2^40 (≈1.1e12). Resolution ~9.1e-13 (resolves w_min=1e-4
  fine); int64 range /2^40 ≈ ±8.4e6 headroom per block partial — ample for per-block weight
  sums. A numerical detail, not a physical constant (cf. Philox multipliers).
- Slots: exclusive prefix-sum of per-particle progeny counts; result is index-defined so it is
  config-independent by construction. Simple correct scan for M4-T1 (per-tile scan + host
  scan of tile sums + add base); fast scan deferred to perf.
- CUDA-guard everything: `nukesim_gpu` lib + `test_gpu` only built under `NUKESIM_WITH_CUDA`,
  so CPU-only CI stays at 75 green. `gpu.` test prefix, anchored `^gpu\.`.
